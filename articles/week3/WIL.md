### 미션2: Persistence Contect 이해하기

- JPA = ORM이며 객체 지향과 datanase간 발생하는 차이를 매핑해줌
: 객체는 객체대로 설계, DB와의 차이점은 ORM을 통해서 매핑 통해 “객체중심”으로 개발을 할 수 있게됨

---

- 영속성 컨텍스트
1. entity의 영속화에 관여, entity들이 db로 바로 가지 않고 entity를 저장하는 환경으로 역할
- JPA는 ORM을 위한 인터페이 표준 / Hibernate는 ORM의 실제 엔진(구현체)
- entity = 데이터베이스 테이블과 1:1로 매핑되는 자바 클래스
→ DB데이터를 자바 객체처럼 사용하기 위해서
- entity manager = JPA가 엔티티를 DB와 연결해주는 관리자/엔진
→ entity를 실제로 DB에 저장/조회/수정/삭제 하는 사람

⇒ ex.. 엔티티= 책의내용(클래스), 엔티티 매니저= 도서관사서

- 영속성 컨텍스트 = 엔티티매니저가 관리하는 공간(저장소)
→ 즉  엔티티매니저가 영속성 컨텍스트를 사용해서 일을 하는것
→ 엔티티 니저는 영속성 컨텍스트를 생성/관리
- 하는일: 엔티티 캐시(한 번 조회한 엔티티를 메모리에 저장해두고 계속 씀), 변경감지(Dirty Check), 쓰기지연(INSERT/DELETE를 모아두었다가 한 번에 실행→ 트랜잭션 commit시점에만 실행됨)

⇒ 성능 최적화/ 일관성 유지

---

- 엔티티의 영속화: 엔티티를 영속성 컨텍스트에 넣어서 JPA가 관리하도록 만드는것, 엔티티가 JPA관리대상이 되는것 
→ ex.. 비영속= 회원가입전 / 영속= 회원가입한 순간

```java
EntityManager.persisit(entity) // 매서드 
```

- 엔티티의 영속화가 된다면 ..?
1. 1차캐시에 저장 : DB까지 가지않고 메모리에서 찾을 수 있음
2. 변경감지 활성화  : 값만 바꿔도 UPDATE실행
3. 동일성 보장 : 같은 엔티티 두 번 조회해도 동일 객체 반환
4. 쓰기 지연

---

- 트랜잭션 = 작업을 하나의 묶을으로 처리
ex. 은행송금
1. A계좌 -10만원
2. B계좌 +10만원
: 2가지의 경우를 모두 성공해야 정상, 이걸 한 묶음으로 처리하는 것이 트랜잭션 (모두성공/아무것도 안할걸로 되될리기)
→ 그래서 스프링에서는 `@Transactional` 메서드를 사용해서 같이 해야하는 작업들을 묶고 하나라도 오류나면 되돌리고 오류 없이 끝나면 DB에 반영

---

- Transaction에서 작업을 수행할때 em은 영속성 컨텍스트가 하나라도 존재한다면(DB를 부르는 아무튼 작업이 있었다면 이미 만들어졌을테니까..) 그거 사용하고 없으면 영속성 컨텍스트르 생성, 그리고 다쓰면 영속성 컨텍스트 종료후 삭제됨
→ 트랜잭션이 곧 영속성 컨텍스트의 생명주기

---

- Extened 영속성 컨텍스트
트랜잭선이 끝나도 사라지지 않음, 여러 트랜잭션동안 살아 있을 수 있을 수 있음
- 여러 트랜잭션이 한 영속성 컨텍스트를 공유할 수 있음
- 존재이유
: 여러 화면, 여러 요청에 걸쳐 같은 엔티티를 계속 들고다니면서 수정하고 마지막에 한 번에 저장하려고@!
: 여러단계로 이루어진 사용자 입력(위자드, 단계별 폼)같은 UI를 지원하기 위해서

### 미션3: Repository 계층 어노테이션

1. `@Repository` 
* 레포지토리 어노테이션을 사용하는이유 
: Bean등록 - @Repository 어노테이션을 사용하면 해당 클래스가 스피링의 Bean으로 등록되어 Coponent Scan을 통해 자동으로 인식됨
: 예외 변환 - 스프링 데이터 JPA는 데이터 엑세스 작업 중 발생하는 예외를 스프링이 제공하는 DataAccessExpception 계층 구조의 예외로 변환하여 처리하며 @Repository 어노테이션은 이 예외 변환 기능을 활성화하는 역할을 수행함
: 의미전달 - @Repository 어노테이션은 해당 클래스가 데이터 접근 계층의 구현체임을 명시적으로 표현하며 코드의 가독성과 유지 보수성을 높임
2. `@Transactional`
* 트랜잭션이란 
= 데이터베이스 관리 시스템 또는 유사한 시스템에서 상호작용의 단위 
= ACID(원자성, 일관성, 독립성, 지속성)으로 데이터베이스 트랜잭션이 안전하게 수행된다는 것을 보장
* 트랜잭션 어노테이션을 사용하는 이유
: 클래스나 메서드에 붙여줄 경우,해당 범위 내 메서드가 트랜잭션이 되도록 보장해준다
: 직접 객체를 만들 필요 없이 선언만으로도 관리를 용이하게 해줌
: 연산이 고립되어서 다른 연산과의 혼선으로 인해 잘못된 값을 가져오는 경우가 방지됨
: 연산의 원자성이 보장되어서 연산이 도중에 실패할 경우 변경사항이 commit되지 않음
3. `@Entity` 
* Entity 어노테이션이란
: JPA를 사용해서 테이블과 매핑할 클래스에 붙여주는 어노테이션
: 어노테이션을 붙임으로써 JPA가 해당 클래스를 관리하게됨 
    
    ```java
    @Entity(name = "user2")
    public class User {}
    ```
    
    → name 을 쓰면 JPA에 사용할 엔티티 이름을 지정할 수 있고 쓰지 않을 경우에는 default 클래스 이름을 엔티티 이름으로 지정한다 
    : 기본 생성자가 꼭 필요하며 final, enum, interface, inner class에서는 사용불가, 필드(변수)를 final로 선언 불가함
